# Bounded failure diagnostics — source candidate, never a producer proof

[FACT] Interface: `python3 ci/export-diagnostics.py --profile ci/diagnostics-profile.json --output "$RUNNER_TEMP/release" --destination "$RUNNER_TEMP/build-diagnostics" --exit-file "$RUNNER_TEMP/native-build.exit" --build-outcome failure`. Outcomes are success/failure/cancelled/skipped/unknown. Run in an always condition; upload only the NEW build-diagnostics directory in an always condition. The native step records its actual local exit in the sibling native-build.exit and exits with that same status. Collector success cannot change that earlier step. Cancellation/worker loss may prevent either always step from executing; missing uploads remain missing evidence.

[FACT] Profiles are code-reviewed literal JSON in workflow-definition W. Their canonical hashes are embedded in this exporter; changed/widened profiles are refused. Schema is `{schema:1,repository,files:[literalRelativePath],directories:{literalNonrecursiveDirectory:anchoredBasenameRegex}}`. OpenShell and AIRC have separate closed lists. No recursive output, source, work, Cargo/target/cache, home, public-keyring, binary/archive or publication traversal is available. Shared publisher and success publication inventory are untouched.

[FACT] The native builder writes BUILD-OWNER.json immediately after creating its own NEW output, before command/build effects. Exact closed keys are schema1, repository, source_subject (fixed source commit), workflow_definition (BUILD_DEFINITION=GITHUB_SHA), run_id, run_attempt, arch; all values are validated public CI identity. The exporter matches the whole marker against current GitHub environment, checks canonical absolute output, uses no-follow component opens and verifies the top output root and ownership marker UID against the CI process UID. After that admission, only exact repository-specific inner FILE leaves selected by reviewed code plus actual pinned-profile membership may allow the CI UID or expected native-container writer UID0. Every directory, ancestor and host-generated profile record remains strict CI-UID; all other UIDs remain refused. Existing output without this matching ownership record is not adopted. Missing/preflight/unowned/refused output produces metadata-only DIAGNOSTICS.json in the NEW destination, never invented mutation success.

[FACT] Bounds are enforced before capture/list growth: 1MiB/file,32MiB total including a reserved1MiB manifest,256 files including the manifest,512 directory entries scanned globally. Copies use only prebudgeted prefixes. Each regular single-link file from an admitted writer is opened no-follow/nonblocking, fstat-checked before/after for unchanged device/inode/mode/owner/linkcount/size/mtime/ctime, and copied to captured/ at the same relative path. Symlinks,FIFOs,specials,unowned paths and hardlinks are refused. Partial reads or concurrent changes are explicit unstable records. Each captured record includes original_size,captured_size,captured_prefix_sha256,truncated and unchanged. Missing/refused/budget/enumeration limits are explicit. A truncated JSON prefix is raw diagnostics, not parsed proof.

[FACT] DIAGNOSTICS.json always says positive_build_proof:false,complete:false,mutation_outcome:not_inferred. Actions build_step_outcome and the actual local exit-file record are separate. A local timeout/exit124/nonzero/exit0 never proves a controller/container mutation settled. Original request/result_known/uncertain/CID/log bytes are preserved when present, within these bounds; absent data is not reconstructed. The exporter has no Docker, process execution, network, build, cleanup, deletion or replay facility and never changes source output. Destination is exclusive/new; an existing destination is refused rather than overwritten.
