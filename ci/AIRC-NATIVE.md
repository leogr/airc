## R2 correction: admit the effective local native Docker daemon

[FACT — source only] This revision resolves Docker selection before the first pull/create/start mutation. A nonempty `DOCKER_CONTEXT` wins over `DOCKER_HOST`; otherwise `DOCKER_HOST` wins over the configured default context. Default/context selection uses bounded read-only context show/inspect. The selected endpoint must resolve to a local UNIX socket; remote SSH/TCP contexts and host overrides fail as prerequisites. The selected endpoint and canonical socket endpoint are recorded separately, including whether an ignored host override was present. No ignored remote endpoint or environment dump is exported.

[FACT — source only] Native admission reads bounded selected daemon fields (`ID`, `OSType`, `Architecture`, `NCPU`, `MemTotal`, `DockerRootDir`, `ServerVersion`), not proxy/config/auth fields. The actual daemon must report Linux, the requested native architecture, at least two CPUs and 4GiB RAM. Its DockerRootDir must resolve to an existing local directory. Both output and DockerRootDir require a native ext/xfs/btrfs/zfs backing filesystem and 20GiB free at admission. Preserved later floors are 16GiB before pull and 14GiB before/during builds, with host 4GiB total and 2GiB available RAM. No floor was lowered; jobs2 remains unchanged.

[FACT — source only] Every later Docker command, including pull/create/start/stop/image/container inspection, uses `docker --host <admitted canonical UNIX endpoint>` and an environment with context/host/TLS/API-version selectors removed. This prevents an environment/config context change from selecting a new daemon after admission. The dedicated trusted worker premise remains necessary; this is not a hostile-root/socket-proxy exclusion proof.

## R4 correction: retain bounded diagnostics after failed native builds

[FACT — source only] After source/workflow/CI preflight and immediately after creating its own new output directory, the builder writes and fsyncs `BUILD-OWNER.json` before any registry or Docker effects. Its closed schema is `{schema:1,repository,source_subject,workflow_definition,run_id,run_attempt,arch}`; source is the fixed AIRC commit for manual dispatch or the actual tagged S for a published event; definition equals the validated workflow SHA, architecture matches `BUILD_ARCH`, and run/attempt are bounded positive decimal identities. An existing output is never adopted or replaced. The marker establishes ownership only; it never claims an effect ran, settled, or succeeded.

[FACT — fixed profile] `diagnostics-profile.json` is a closed source-controlled profile for the shared diagnostics exporter. Literal paths include the owner marker, failure marker, pull intent/result log, public image metadata, daemon admission/monitoring, and each build's create/start/stop intent/result, completed inspect and container log. Nonrecursive directory patterns select only raw host/admission command stdout/stderr, native ELF/version/help stdout/stderr, unchanged upstream/build/release-test stdout/stderr/status and compiler/package inventories. It excludes source archives, extracted source, Cargo/target/cache trees, homes, credential stores, release binaries/archives and generic workspace contents. The shared exporter independently enforces the exact reviewed profile; a runtime profile edit cannot widen it.

[PROPOSAL — workflow integration] The workflow records the actual native builder exit status in its own `native-build.exit` file outside the build output, then invokes the shared exporter in an always-run step with `--profile`, `--output`, a new `--destination`, `--exit-file` and `--build-outcome success|failure|cancelled|skipped|unknown`. Only the separate diagnostic destination is uploaded by the always-run diagnostics artifact step. Export is bounded to 1MiB/file, 32MiB total and 256 files, with explicit missing/truncated/refused/unstable records. Missing output or an absent/mismatched marker yields metadata-only diagnostics and cannot authorize copying arbitrary paths. The exit-file bytes and actual build-step outcome are retained separately; exporting or uploading diagnostics cannot convert a failing native build into success.

[FACT — unchanged publication contract] `BUILD-OWNER.json` is not added to successful `publication/`, and the successful release artifact/proof/raw-evidence inventory is unchanged. Diagnostics are not release assets, successful build proof, consumer qualification or recovery authority. The exporter invokes no Docker action, build, cleanup, deletion, retry or replay. Failed or lost command replies remain failed/uncertain in the original logs and intents; absent result files remain absent. Preflight failure before output creation is explicit, without fabricating an effect result. Runner loss or forced cancellation may prevent any always-run step or upload; no durable transport is claimed for those unavailable executions.

[UNRUN] This source correction has AST parsing only. Pure controls are authored for ownership before effects, malformed CI identity, existing output refusal, setup/nonzero/lost-reply failure retention, preflight with no output, fixed profile boundaries and unchanged success publication selection. The shared exporter owns its bounded-copy and failure-path tests. No tests, Docker, Rust, network, Go, runtime or cleanup ran while authoring this slice. Original snapshots, native daemon admission and the accepted shared publisher remain unchanged.
